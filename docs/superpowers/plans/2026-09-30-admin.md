## Contrat commun

La passerelle reçoit `POST {action, resource?, id?, search?, status?, page?, payload?, expectedVersion?, requestId?}`.

```ts
type AdminRole = 'owner' | 'moderator' | 'support' | 'editor';
type Resource = 'users' | 'hosts' | 'properties' | 'bookings' | 'tickets' | 'reports' |
  'faq_items' | 'guides' | 'guide_categories' | 'articles' | 'courses' | 'course_steps' |
  'legal_documents' | 'errors' | 'limits' | 'cleanup' | 'audit' | 'members';
type RecordData = Record<string, unknown>;
type Page = { rows: RecordData[]; total: number; page: number; pageSize: number };
// action=session -> {user:{id,email},role,mfaRequired:boolean}
// action=list,resource -> Page; action=detail,resource,id -> {record:RecordData,related:RecordData}
// action=overview -> {counts:Record<string,number>,recent:RecordData[]}
// action=document,id(host UUID),payload:{key:string} -> {url:string,expiresIn:60}
// action=mutate,resource,id?,payload:{operation:string,...},expectedVersion?,requestId -> {ok:true,...}
```

SQL : `admin_query(p_actor uuid,p_resource text,p_id uuid,p_search text,p_status text,p_page integer)` ; `admin_mutate(p_actor uuid,p_resource text,p_id uuid,p_payload jsonb,p_expected_version text,p_request_id uuid)`. `overview` et `session` sont aussi des ressources serveur. Les fonctions sont réservées à `service_role` et revérifient l’opérateur. Chaque détail renvoie `record.version` comme jeton opaque de concurrence. Les mutations existantes exigent ce jeton ; la création n’en exige pas.

Opérations : `users:suspend|reactivate`, `hosts:approve|reject`, `properties:publish|return|suspend|review`, `tickets:reply|update`, `reports:freeze|resolve`, contenus `save_draft|publish`, `limits:update`, `members:grant|revoke`. Motif `note` exigé pour les décisions. Publications éditoriales utilisent `payload.fields`; brouillons séparés, sans écriture publique avant publication. Réservations et suivi technique en lecture seule.
